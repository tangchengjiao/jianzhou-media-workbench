# Phase 2.1：对标平台与扫描策略修订

验收日期：2026-08-04

## 本轮修订结论

本轮消除了三个直接影响可用性的断点：抓取数量不再被固定选项限制；对标入口覆盖更多主流平台；导航分组不再在页面切换时自动收起。抖音真实数据链路已完成最小计费的端到端验收，其他平台保持“已映射、待真实样本验收”的诚实状态。

## 产品行为

1. 添加对标账号时可输入 1–500 的整数目标条数。界面显示估算分页次数，平台提前返回无更多作品时停止。
2. 平台注册表统一提供抖音、小红书、视频号、B站、快手、微博和 TikTok 的名称、账号标识说明与输入提示；前端和后端使用同一份服务端目录。
3. 相同用户、平台和账号重复添加时执行刷新并更新目标条数，不创建重复账号。
4. 导航的基础、洞察、创作、复盘四组默认展开。进入其他页面不会改变分组状态；用户手动收起后仅在本机浏览器保存偏好。
5. Real 模式绝不降级为演示数据；缺少密钥、平台解析失败、接口鉴权失败或余额/限流均返回分阶段错误。

## 数据与迁移

- 数据库 schema v4 增加 `benchmark_accounts.scan_count`，旧的 30/60/全部迁移为 30/60/200。
- 目标条数在服务端再次校验并限制为 1–500；分页拉取最多 50 页并按作品 ID 去重。
- Provider 的 `Authorization` 自动使用 Bearer 方案；密钥只从环境变量或 Windows 加密存储读取，不写入项目文档、代码、日志或普通 SQLite 字段。
- TikHub 主域名与中国大陆加速域名都进入受控出站允许列表，其他域名仍需显式配置。

## 当前边界与下一步

- 非抖音平台没有在本轮使用真实账号逐一计费测试，因此不可宣称已经生产可用。
- TikTok 单次接口页大小、B站页码、微博页码以及小红书/快手游标由适配配置处理；目标条数是“最多保存数量”，不是供应商保证返回数量。
- 非抖音平台的全文提取按钮在 Real 模式暂不开放，避免把尚未验收的作品文本适配器展示为可用。
- 下一步优先收集其他六个平台各一个公开账号样本，按平台依次完成真实链路、脱敏契约样本、限流/余额错误和字段漂移测试。

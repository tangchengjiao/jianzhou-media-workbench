# 自媒体个人运营工作台｜产品需求文档 PRD V2.0

> 文档状态：可进入产品原型与技术开发阶段  
> 产品形态：本地优先的个人创作者运营工作台  
> 目标用户：个人IP创作者、知识类博主、自媒体从业者、轻量内容团队中的主理人  
> 核心原则：总控串联、页面单职、数据可换、按需加工、全程可追溯、失败不伪装

---

## 0. 本次版本调整说明

V2.0 不再把大量功能压缩到五个页面，而是重新按照用户真实任务拆分页面。

本次调整的核心包括：

1. 将“工作总台”定义为总控与调度中心，不承载复杂编辑功能。
2. 将“IP档案”从静态表单升级为独立的IP理解与语音访谈中心。
3. 将“内容发现、内容提取、内容拆解、个人化创作”拆成连续但独立的页面。
4. 将用户自己的账号、对标账号、历史内容、语料、资料、规则统一抽象为可挂载的外部数据包。
5. 明确区分自动监控与用户主动触发的高成本动作。
6. 写死“禁止静默兜底”：不能伪造成功、不能隐藏错误、不能自动切换到未授权的替代路径。
7. 保留 `cheat-on-content` 的校准思想，但将其嵌入内容发布与复盘链路，而不是照搬其命令式交互。

# 1. 产品定义

## 1.1 一句话定义

一套面向个人创作者的运营工作台：持续同步账号与对标的公开信号，按需提取和拆解内容，结合创作者自己的IP档案、语料和运营目标生成选题与文案，并通过发布后的数据复盘不断沉淀个人内容经验。

## 1.2 产品不是什​​么

本产品不是：

- 企业级项目管理系统；
- 多人协作审批平台；
- 自动洗稿工具；
- 单纯的数据看板；
- 只负责生成文案的AI写作工具；
- 默认下载、转写和分析所有内容的高成本爬取系统；
- 用模糊结果掩盖接口失败的“看似能跑”Demo。

## 1.3 产品最终帮助用户回答的问题

用户每次打开产品，最终只需要解决以下问题：

1. 我现在的IP定位和运营目标是什么？
2. 我的账号最近发生了什么变化？
3. 外面最近有哪些内容值得我关注？
4. 哪些内容值得进一步提取、学习或转成我的选题？
5. 这条内容应该怎么变成符合我风格的稿子？
6. 我本周应该发多少、先做哪一条？
7. 发布结果与当初的判断是否一致？
8. 哪些经验应该沉淀为自己的长期规则？

# 2. 第一性原理

## 2.1 用户真正购买的不是功能，而是连续决策能力

个人创作者的问题不是完全没有工具，而是工具和信息彼此割裂：

- 对标内容在一个收藏夹；
- 热点在另一个平台；
- 自己的定位写在文档里；
- 脚本散落在文件夹；
- 发布数据留在平台后台；
- 复盘依靠记忆；
- 下一次创作又重新从零开始。

因此产品的核心价值不是继续增加更多工具，而是把一次内容从来源到结果完整串联。

## 2.2 核心闭环

```text
外部信号与内部信息
        ↓
判断是否值得处理
        ↓
用户主动提取与拆解
        ↓
结合IP生成自己的选题
        ↓
生成、修改并安排内容
        ↓
发布并回收数据
        ↓
验证当初判断
        ↓
沉淀个人经验与规则
        ↓
影响下一轮推荐
```

## 2.3 产品必须降低的五类成本

| 成本 | 用户表现 | 产品应提供的能力 |
|---|---|---|
| 决策成本 | 不知道做什么 | 结合IP、账号、对标和热点给出有依据的推荐 |
| 搜集成本 | 多平台来回切换 | 自动同步低成本公开信号，统一呈现 |
| 加工成本 | 视频看完还要手抄 | 用户主动触发字幕获取、ASR、清洗和拆解 |
| 执行成本 | 选题很多但发不出去 | 选题、稿件、计划和发布状态连续流转 |
| 学习成本 | 发完只看到数字 | 发布前判断、发布后对比、经验沉淀 |

## 2.4 每个页面只回答一个主问题

页面数量可以增加，但每个页面必须保持单一职责。用户进入页面后，应能在三秒内理解：

- 这里是做什么的；
- 我的下一步动作是什么；
- 完成以后会流向哪里。

# 3. 目标用户与典型场景

## 3.1 核心用户

### A. 正在起号的个人创作者

需求：找到定位、建立内容方向、学习对标、形成稳定更新节奏。

### B. 已经稳定更新的创作者

需求：减少选题焦虑、提升内容质量、监控账号变化、形成自己的内容规律。

### C. 同时经营多个平台的个人IP

需求：统一管理内容来源、稿件版本、发布安排和各平台表现。

### D. 有大量既有资料的专业创作者

需求：把课程、直播、文章、历史脚本和个人观点变成可检索、可调用的IP资料包。

## 3.2 典型使用场景

### 场景一：第一次建立IP档案

用户进入“IP档案”，选择语音访谈。系统以内容操盘手的身份提问，了解其经历、专业能力、目标用户、观点、表达习惯与商业方向。访谈结束后生成结构化档案，用户逐项确认后写入正式版本。

### 场景二：监控到一个对标爆款

系统只同步该作品的公开元数据和表现信号。用户点击“提取文案”后，系统才检查字幕、下载媒体或执行ASR。完成后用户可以进入“内容拆解”，再点击“转为我的选题”。

### 场景三：导入自己过去的脚本

用户在“资料中心”导入Markdown、Word导出的文本、CSV或历史脚本文件。系统先预览和字段映射，默认只保存。用户选中部分资料后再主动执行分析、风格提取或加入IP语料。

### 场景四：安排本周更新

用户在“账号运营”设定本周目标与可投入时间。系统结合内容库存、历史执行能力和当前策略，在“内容计划”中给出建议数量，用户确认后安排。

### 场景五：发布后复盘

作品发布后，系统按设置同步公开数据。到复盘时间后，系统将发布前判断、实际数据、评论反馈和用户主观感受放在一起，提出规则更新建议。只有用户确认后，规则才进入有效经验库。

# 4. 产品总架构

## 4.1 总控层与工作层

产品分为两种页面：

### 总控层

- **工作总台**：展示全局状态、重要信号、待办任务和跨页面调度入口。

### 工作层

- **IP档案**：理解创作者本人；
- **账号运营**：管理账号状态、目标和更新节奏；
- **内容雷达**：发现值得关注的外部信号；
- **内容提取**：按需获取文案、评论和媒体信息；
- **内容拆解**：理解内容结构与可复用模式；
- **创作工坊**：生成自己的选题、提纲和文案；
- **内容计划**：安排制作、发布和库存；
- **数据复盘**：回收数据并验证判断；
- **成长记录**：查看IP、策略和规则如何变化；
- **资料中心**：管理所有外部数据包；
- **系统设置**：配置数据源、模型、预算和本地环境。

工作总台不复制这些页面的全部功能，只展示摘要并把任务调度到对应页面。

## 4.2 推荐侧边栏

为兼顾清晰、对齐和认知一致性，侧边栏使用四字名称，并按任务阶段分组。

```text
总览
  工作总台

基础
  IP档案
  账号运营

洞察
  内容雷达
  内容提取
  内容拆解

创作
  创作工坊
  内容计划

复盘
  数据复盘
  成长记录

资产
  资料中心

系统
  系统设置
```

### 命名原则

- 每个页面名称控制在四个字符或视觉上等宽；
- 不使用含义模糊的“中心”“智能”“系统”等泛化名称作为主要区分；
- 页面名优先使用用户能理解的动作或对象；
- 分组名不超过两个汉字，降低侧边栏密度；
- 固定宽度图标区和文字区，保证视觉对齐；
- 导航分组支持折叠，默认只展开当前工作组，避免十二个入口同时争夺注意力；
- “工作总台”始终固定在顶部，“资料中心”和“系统设置”固定在底部。

# 5. 核心对象与数据包模型

## 5.1 为什么需要数据包

产品不能把某个创作者的信息写死在业务代码里。换一个用户时，应通过切换数据包完成，而不是修改提示词、字段或代码。

## 5.2 数据包类型

| 数据包 | 主要内容 | 被哪些页面使用 |
|---|---|---|
| IP资料包 | 定位、经历、观点、表达风格、案例、禁用表达 | IP档案、内容拆解、创作工坊 |
| 账号数据包 | 自有账号、账号快照、历史作品、后台导入数据 | 账号运营、内容计划、数据复盘 |
| 对标数据包 | 对标账号、作品元数据、样本、评论 | 内容雷达、内容提取、内容拆解 |
| 内容语料包 | 自己的历史脚本、文章、直播转写、课程资料 | IP档案、创作工坊 |
| 用户反馈包 | 评论、私信问题、直播提问、客户反馈 | 内容雷达、创作工坊、数据复盘 |
| 规则经验包 | 已验证规律、待验证假设、失效规则 | 创作工坊、内容计划、数据复盘 |
| 运营周期包 | 当前阶段、目标、产能、内容比例、时间范围 | 工作总台、账号运营、内容计划 |

## 5.3 数据包基本规则

每个数据包必须具备：

- 唯一ID；
- 数据包类型；
- 所属用户；
- 版本号；
- 来源列表；
- 创建和更新时间；
- 当前是否启用；
- 可见范围；
- 内容摘要；
- 完整来源追溯；
- 可导出和可删除能力。

## 5.4 多用户切换原则

切换创作者时，系统执行：

1. 关闭当前激活的数据包组合；
2. 激活新用户的IP、账号、语料、对标和规则包；
3. 清空会话级临时上下文；
4. 保留系统级模型和数据源配置；
5. 禁止跨用户检索和生成。

# 6. 页面详细设计

## 6.1 工作总台

### 页面定位

全局状态与调度中心。

### 页面回答的问题

> 我现在最应该处理什么？

### 核心区域

#### A. 当前运营状态

展示：

- 当前IP版本；
- 当前运营阶段；
- 本周目标；
- 计划发布数量；
- 已完成数量；
- 内容库存；
- 待提取、待拆解、待发布、待复盘数量；
- 本周剩余可投入时间。

#### B. 今日行动队列

系统按照优先级展示最多五项：

- 账号异常需要查看；
- 对标出现高表现内容；
- 某条来源内容等待用户决定是否提取；
- 某条稿件需要继续修改；
- 某条作品到达复盘时间；
- 本周排期与实际产能不匹配。

每项必须有明确按钮，例如：

- 查看账号；
- 去提取；
- 去拆解；
- 继续创作；
- 开始复盘；
- 调整计划。

#### C. 重要信号

只展示经过阈值筛选的重要变化，不展示普通流水：

- 自有账号增长异常；
- 对标账号新增高表现内容；
- 某关键词热度上升；
- 用户反馈重复出现；
- 某内容方向连续表现变化。

#### D. 操盘手对话框

用户可以用文字或语音下达跨页面命令，例如：

- “帮我看一下今天最值得处理的内容。”
- “把这个对标视频加入提取队列。”
- “根据我本周的时间重新调整排期。”
- “继续上次的IP访谈。”

总台只负责识别意图、调用明确工具和跳转页面，不在一个对话中偷偷执行所有高成本动作。

### 页面输出

- 全局任务；
- 调度指令；
- 页面跳转；
- 用户确认后的任务创建。

---

## 6.2 IP档案

### 页面定位

建立和维护“系统真正理解我”的个人档案。

### 页面回答的问题

> 我是谁，我为谁创作，我通常怎么表达？

### 核心模块

#### A. IP总览

- IP名称；
- 当前定位；
- 目标用户；
- 核心价值；
- 内容支柱；
- 代表观点；
- 主要产品或转化方向；
- 当前版本；
- 最近更新时间。

#### B. 语音访谈

用户可以选择访谈主题：

- 完整建档；
- 经历与专业能力；
- 用户与问题；
- 内容定位；
- 观点与价值观；
- 商业与产品；
- 表达风格；
- 案例补充；
- 档案纠偏。

##### 访谈流程

```text
选择访谈主题
→ 查看预计问题与时长
→ 开始语音对谈
→ 实时转写
→ 操盘手追问
→ 生成访谈摘要
→ 提取结构化字段
→ 用户逐项确认
→ 创建新的IP档案版本
```

##### 操盘手角色要求

- 不只是问固定问卷；
- 根据用户回答继续追问；
- 遇到抽象表达时要求具体案例；
- 区分用户想成为的形象与已经验证的真实能力；
- 不自动替用户美化经历；
- 不直接覆盖正式档案；
- 所有结论必须能回溯到访谈原文或导入资料。

#### C. 个人语料

支持加入：

- 历史脚本；
- 公众号文章；
- 小红书笔记；
- 直播转写；
- 课程讲义；
- 访谈录音；
- 客户案例；
- 用户自行上传的资料。

每份语料可以标记：

- 是否代表本人真实表达；
- 是否允许用于风格提取；
- 是否允许用于事实引用；
- 是否允许用于生成新稿；
- 有效时间范围。

#### D. 表达画像

系统可以从用户确认的语料中提取：

- 常用句长；
- 口语化程度；
- 开头习惯；
- 论证结构；
- 常用词；
- 禁用词；
- 情绪强度；
- 案例使用方式；
- 自我称呼；
- 用户称呼；
- 结尾方式；
- 常见口头语。

表达画像是可编辑的建议，不是不可更改的事实。

#### E. 档案版本

任何正式修改都生成版本：

- 变更内容；
- 变更原因；
- 来源；
- 生效时间；
- 操作者；
- 与上一版本差异。

### 页面输出

- IP资料包；
- 表达风格包；
- 事实与案例库；
- 最新激活版本。

---

## 6.3 账号运营

### 页面定位

管理自己的账号、目标、节奏和实际执行能力。

### 页面回答的问题

> 我的账号现在是什么状态，这个周期应该怎么运营？

### 核心模块

#### A. 自有账号

- 添加账号链接或平台ID；
- 绑定TikHub数据源；
- 设置同步频率；
- 查看最近同步时间；
- 手动同步；
- 查看接口错误；
- 导入平台后台数据。

#### B. 当前运营周期

字段包括：

- 周期名称；
- 起止日期；
- 当前阶段；
- 核心目标；
- 重点平台；
- 重点内容方向；
- 每周可投入时间；
- 计划更新数量；
- 可接受的制作复杂度；
- 是否处于推广期；
- 本周期重点实验。

#### C. 更新节奏

可选择：

- 高频冲刺；
- 稳定更新；
- 低频维护；
- 内容测试；
- 产品预热；
- 转化推广；
- 暂停休整；
- 自定义模式。

系统根据用户的历史完成率提示建议，但不能强制把“多发”当作默认正确答案。

#### D. 账号数据

显示：

- 粉丝与互动趋势；
- 发布频率；
- 最近作品；
- 高于平均的作品；
- 低于平均的作品；
- 内容方向分布；
- 计划与实际差异。

#### E. 运营建议

建议必须显示依据：

- 来自账号数据；
- 来自当前运营目标；
- 来自历史规则；
- 来自内容库存；
- 来自用户可投入时间。

### 页面输出

- 账号数据包；
- 当前运营周期包；
- 更新节奏；
- 可用于内容推荐和排期的约束条件。

---

## 6.4 内容雷达

### 页面定位

统一发现值得关注的外部和内部内容信号。

### 页面回答的问题

> 最近有什么内容值得我进一步看？

### 信号来源

- 对标账号新作品；
- 对标高表现作品；
- 关键词搜索；
- 平台热点；
- 用户反馈；
- 自己历史内容重新起量；
- 手动收藏；
- 外部导入数据。

### 信号卡字段

- 来源类型；
- 平台；
- 作者；
- 标题或描述；
- 链接；
- 发布时间；
- 公开互动数据；
- 相对表现；
- 与当前IP的相关度；
- 时效性；
- 是否已处理；
- 数据来源与抓取时间。

### 每张卡允许的动作

- 加入观察；
- 获取评论；
- 提取文案；
- 深度拆解；
- 转为选题；
- 忽略；
- 不再推荐相似内容。

高成本动作不能因页面滚动、卡片展开或系统刷新自动执行。

### 页面输出

- 信号；
- 用户选择的待处理来源；
- 提取任务；
- 选题候选。

## 6.5 内容提取

### 页面定位

按需将外部内容变成可保存、可检索、可继续拆解的文本资产。

### 页面回答的问题

> 我需要从这条内容中拿到哪些原始材料？

### 内容来源

- 雷达卡片；
- 用户粘贴链接；
- 用户上传视频或音频；
- 用户导入文本；
- 资料中心中的已有资产。

### 提取动作

#### A. 获取原生文本

- 平台正文；
- 视频描述；
- 原生字幕；
- 文章正文；
- 已存在的缓存。

#### B. 语音转写

仅在用户点击后执行：

```text
检查是否已有字幕
→ 检查是否已有缓存
→ 展示执行计划和成本
→ 用户确认
→ 获取媒体
→ 提取音频
→ ASR转写
→ 保存原始转写
→ 可选执行清洗
```

#### C. 评论获取

评论同样按需触发，可选择：

- 热门评论；
- 指定数量；
- 全量分页范围；
- 只保存；
- 保存后聚类。

### 执行前确认卡

必须显示：

- 将调用的数据源；
- 是否需要下载媒体；
- 预计媒体大小；
- 预计音频时长；
- 使用的ASR模型；
- 预计费用；
- 是否已有缓存；
- 将产生哪些文件；
- 原始媒体保留策略。

### 资产分层

- 原始媒体；
- 原始字幕；
- 原始ASR转写；
- 清洗文案；
- 评论原始数据；
- 来源元数据。

### 页面输出

- 来源内容资产；
- 转写资产；
- 评论资产；
- 可进入“内容拆解”的任务。

## 6.6 内容拆解

### 页面定位

理解一条或一组内容为什么有效，以及哪些模式可以学习。

### 页面回答的问题

> 这条内容的可复用结构是什么？

### 单条拆解

字段包括：

- 核心选题；
- 目标受众；
- 用户问题；
- 开头钩子；
- 内容结构；
- 关键转折；
- 论据与案例；
- 情绪机制；
- 金句与记忆点；
- 结尾动作；
- 评论触发点；
- 可借鉴部分；
- 不应照搬部分。

### 组合拆解

支持同时选择高、中、低表现样本，比较：

- 相同主题下的结构差异；
- 开头差异；
- 时长差异；
- 表达密度；
- 评论反馈差异；
- 可能有效但尚未验证的模式。

### 内容模式卡

拆解结果可以保存为模式卡：

- 模式名称；
- 适用内容类型；
- 适用平台；
- 来源样本；
- 证据数量；
- 当前置信度；
- 是否适合当前IP；
- 是否已经被本人验证。

### 页面输出

- 内容模式；
- 差异化机会；
- 可转入创作工坊的选题候选。

## 6.7 创作工坊

### 页面定位

把外部内容、用户反馈和个人观点转化为自己的选题与稿件。

### 页面回答的问题

> 这件事应该如何用我的身份、观点和语言讲出来？

### 创作入口

- 从内容雷达转入；
- 从内容拆解转入；
- 从用户反馈转入；
- 从历史内容延伸；
- 用户手动创建；
- 操盘手对话创建。

### 创作流程

```text
选择参考来源
→ 明确本条目标
→ 判断是否符合当前IP
→ 生成差异化方向
→ 用户选择方向
→ 生成提纲
→ 补充本人事实和案例
→ 生成初稿
→ 风格适配
→ 原创性检查
→ 用户修改并锁定版本
```

### 差异化方向

至少提供三类明显不同的迁移：

- 同问题，不同观点；
- 同结构，不同案例；
- 相邻问题延伸。

不得只生成同义词替换版本。

### 稿件工作区

- 选题卡；
- 参考来源；
- 目标用户；
- 内容目标；
- 差异化角度；
- 提纲；
- 正文；
- 平台版本；
- 修改记录；
- 引用和事实来源；
- 风格检查；
- 重复度检查；
- 发布前判断。

### 发布前判断

借鉴校准式创作逻辑，记录：

- 本条内容目标；
- 预计相对表现；
- 主要优势；
- 主要风险；
- 本次准备验证的假设；
- 系统置信度；
- 用户自己的判断。

发布后该版本不可覆盖，只能追加复盘。

### 页面输出

- 自己的选题；
- 稿件版本；
- 发布前判断；
- 可加入内容计划的内容项目。

## 6.8 内容计划

- 制作中；
- 待发布；
- 已发布；

显示：

#### C. 日历与看板

# 7. 跨页面联动设计

## 7.1 页面不是孤岛

每个对象都必须保留来源和下一步动作。

### 示例链路

```text
内容雷达：发现对标作品 A
        ↓ 点击“提取文案”
内容提取：获得原始转写 B
        ↓ 点击“深度拆解”
内容拆解：生成模式 C
        ↓ 点击“转为我的选题”
创作工坊：生成选题 D 和稿件 E
        ↓ 点击“加入本周”
内容计划：创建发布任务 F
        ↓ 标记已发布
数据复盘：回收数据 G
        ↓ 用户确认规则
成长记录：新增经验 H
```

任何一步都能返回上游查看依据。

## 7.2 全局对象状态

| 对象 | 关键状态 |
|---|---|
| 信号 | 新发现、已查看、已观察、已忽略、已转任务 |
| 提取任务 | 待确认、排队中、执行中、成功、失败、已取消 |
| 来源内容 | 仅元数据、已有正文、已有字幕、已转写、已清洗 |
| 拆解任务 | 待处理、执行中、已完成、需人工确认、失败 |
| 内容项目 | 候选、已选题、写作中、制作中、待发布、已发布、待复盘、完成 |
| 规则建议 | 待审核、已接受、已拒绝、已失效 |
| 数据包 | 草稿、激活、已归档、已删除 |

## 7.3 工作总台调度规则

总台可以：

- 创建任务；
- 跳转页面；
- 查询状态；
- 汇总结果；
- 提醒用户确认。

总台不可以：

- 未经确认执行高成本动作；
- 自动覆盖IP档案；

- 自动切换数据包；

# 9. 语音操盘手设计

## 9.1 两种语音模式

### IP访谈模式

用于深度了解创作者并更新IP档案。

### 快速指令模式

用于：

- 记录灵感；
- 创建选题；
- 添加运营备注；
- 调整计划；
- 查询工作总台；
- 发起明确任务。

两者必须分开。快速指令不能在无明确确认的情况下修改正式IP档案。

## 9.2 访谈产物

每次访谈保存：

- 原始音频或用户选择不保留；
- 完整转写；
- 对话轮次；
- 访谈摘要；
- 提取字段；
- 证据引用；
- 用户确认结果；
- 新档案版本。

## 9.3 访谈质量规则

- 一次只追问一个问题；
- 尽量要求真实案例；
- 区分事实、观点、计划和假设；
- 对冲突信息必须要求用户确认；
- 不将模型推断直接写成用户事实；
- 不因为访谈中断而生成“完整档案成功”的假结果。

# 10. 无静默兜底原则

用户所说的“不要兜底代码”，在产品层定义为：

# 禁止静默降级、伪造成功和隐藏失败

## 10.1 明确禁止

- TikHub失败后自动返回本地假数据；
- ASR失败后把视频描述冒充完整文案；
- LLM失败后返回固定模板并显示“分析完成”；
- 模型不可用时自动切换到另一个未告知模型；
- 字段缺失时用模型猜测并写入事实字段；
- 下载失败后创建空文件并继续后续任务；
- 导入部分失败却显示整个批次成功；
- 捕获所有异常后只显示“系统繁忙”。

## 10.2 正确行为

发生错误时必须显示：

- 失败阶段；
- 错误代码；
- 具体原因；
- 使用的数据源或模型；
- 是否产生费用；
- 已完成哪些步骤；
- 是否有部分产物；
- 用户可以采取的修复动作；
- Trace ID。

## 10.3 允许的恢复方式

恢复必须是显式的：

- 用户修复配置后重试；
- 用户明确选择另一模型；
- 用户明确选择文字模式代替语音模式；
- 用户选择从缓存继续；
- 用户选择保留部分导入结果或全部回滚。

这些是用户决策，不是隐藏的自动兜底。

# 12. 产品验收标准

## 12.1 信息架构

- 用户能在三秒内理解每个页面职责；
- 侧边栏名称视觉对齐；
- 一个页面不承担两个完全不同的主任务；
- 工作总台可以跳转到所有待处理工作；
- 页面之间保留来源与返回路径。

## 12.2 IP档案

- 支持文字和语音访谈；
- 访谈结果必须经用户确认；
- 正式档案可版本化；
- 任意字段可以追溯来源；
- 切换用户后不会检索到上一用户资料。

## 12.3 内容提取

- 未点击时不得自动下载或转写；
- 执行前展示成本和产物；
- 原始转写与清洗文案分开；
- 失败时显示具体阶段和原因；
- 已缓存内容不会重复付费处理。

## 12.4 创作链路

- 来源内容可以一键进入拆解；
- 拆解结果可以一键转为选题；
- 选题可以一键进入创作工坊；
- 稿件可以加入计划；
- 发布结果可以回到原始来源和发布前判断。

## 12.5 无兜底

- 任意外部服务失败不得返回伪成功；
- 任意模型切换必须由用户明确选择；
- 未完成任务不能进入“已完成”状态；
- 所有错误必须有Trace ID；
- 所有写入必须满足结构校验。

# 13. 关键产品决策摘要

1. 页面数量增加，但通过分组和单一职责降低复杂度。
2. 工作总台是总控，不是所有功能的大杂烩。
3. IP档案是产品基础能力，不是一次填写完的静态表单。
4. 语音访谈使用独立流程，访谈结论必须经用户确认。
5. 所有用户信息以外部数据包形式挂载，保证可替换和隔离。
6. 自动化只负责低成本监控，高成本内容加工必须主动触发。
7. 内容发现、提取、拆解、创作、计划、复盘必须保留同一来源链。
8. 校准式复盘保留发布前判断的不可覆盖性。
9. “无兜底”具体落实为无静默降级、无伪成功、无隐藏模型切换。
10. 第一版优先做完整链路，不追求平台数量和生成能力数量。

# Phase 2：内容雷达与对标账号闭环

验收日期：2026-08-04

## 目标与审查结论

用户需要的不是一组演示卡片，而是能从“我想监控谁”开始工作的完整链路。审查前，内容雷达只有信号列表，没有添加对标账号的入口；虽然后端已有部分扫描代码，但账号、作品、分析与后续创作链条在产品层面是断开的。

参考项目 `E:\software\feishu\家居智能体app` 的有效结构是：账号卡片墙 → 账号详情 → 作品监控墙 → 单作品动作/作者分析。当前项目借鉴其任务结构，但没有复制其 JSON 存储、演示兜底或不可验证的成功返回。

## 已实现闭环

1. 内容雷达顶部提供“添加对标账号”主入口，并保留“雷达信号 / 对标账号”双视图。
2. 添加账号支持抖音、小红书、扫描范围与备注；相同用户、平台、账号 ID 自动去重并刷新。
3. 账号卡展示同步状态、粉丝/获赞/作品统计、最近同步时间，并支持刷新、删除和进入详情。
4. 详情页展示作品监控墙，可按全部、热门、点赞和综合分筛选。
5. 单作品可提取文案、进入选题/创作链路、转为内容雷达信号或打开原作品。
6. 作者分析可形成内容方向、表现规律和可借鉴建议，并持久化最近一次结果。
7. 删除账号会级联删除该账号的监控作品，但已转入内容雷达的独立信号会保留。

## 前后端与数据结构

- 前端：`frontend/assets/js/pages/radar.js` 负责信号/账号双视图、添加弹窗、账号详情、作品操作和分析展示。
- API：`app/api/benchmarks.py` 提供添加、列表、详情、扫描、作者分析、删除和作品转信号接口，并执行对象归属校验。
- 领域服务：`app/benchmarks.py` 负责账号解析、原子扫描、同步状态、错误状态和作品转换。
- 数据源：`app/datasource.py` 在 Real 模式强制校验密钥、分页拉取并去重作品；不允许静默回退 Demo。
- 数据库：schema v3 增加同步状态和结构化错误字段，并对 `(user_id, platform, uid)` 建立唯一索引。

## Demo 与 Real 边界

### 已验证

- Demo 模式完整交互、持久化、重复添加、作品转信号和作者分析。
- Real 模式缺少 Key 时返回 `CONFIG_MISSING_API_KEY`，且不创建空账号记录。
- 抖音与小红书的接口路径、参数和字段映射已依据 TikHub 官方文档及参考项目校正。

### 尚未宣称完成

- 当前未提供有效 TikHub API Key，因此真实抖音/小红书请求、计费、限流和响应字段还没有完成带密钥端到端验收。
- 平台封面外链可能受防盗链影响；缺失封面时界面展示真实标题，不伪造图片。
- 定时自动扫描、失败重试队列和扫描历史时间线尚未进入本切片。
- 当前仅支持抖音和小红书；B站、视频号、公众号未开放入口。

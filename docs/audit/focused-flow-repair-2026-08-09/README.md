# 资料—创作—视觉聚焦链路验收

验收时间：2026-08-09  
运行环境：源码开发版，`workspace-schema26-writing-quality-gate`

## 验收结果

| 用户路径 | 修改前问题 | 当前状态 | 证据 |
|---|---|---|---|
| 资产中心 → 稿件版本 → 创作工坊 | 跳转只进入创作页，丢失项目与稿件版本，可能落到空项目 | 通过：URL携带 `project` 与 `draft`，创作页打开指定版本 | `01-assets-drafts.png`、`02-creation-v4.png` |
| AI稿件体检 → 填写补充要求 → 生成新版本 | 要求只被记录，正文可能未改；版本看起来相同 | 通过：要求必须返回正文内可检索证据；近重复拒绝落库；历史旧记录明确警告并可带回重试 | `02-creation-v4.png`、自动化测试 |
| 视觉工厂 → 成品历史 → 图文文档 | 后置CSS把三列覆盖为自适应四列，导致卡片过窄和溢出 | 通过：桌面固定三列，容器窄时再降为两列/一列 | `03-visual-three-columns.png` |

## 数据核查

- “个人知识库”项目中，v2 与 v3 的正文相似度为 100%，确认历史上确实生成过重复版本。
- v3 与 v4 并非完全相同，但主要变化不在首屏，旧界面缺少逐行差异和用户要求落实证据，因此用户无法判断改了什么。
- 新逻辑会拒绝完全相同或相似度不低于 99.8% 的优化稿，不再继续堆积无意义版本。

## 自动化结果

- 全量单元与集成测试：85/85 通过。
- 新增覆盖：准确稿件上下文跳转、父项目命名、用户要求落实证据、重复版本拦截、图文历史三列约束。
- JavaScript 语法检查：`create.js`、`system.js`、`visuals.js` 通过。

## 可访问性边界

本轮验证覆盖了页面渲染、URL深链和主要按钮所需的数据状态；未使用屏幕阅读器完成整站人工朗读测试。现有按钮和表单继续使用原生可聚焦控件，后续仍建议单独做完整键盘与读屏验收。

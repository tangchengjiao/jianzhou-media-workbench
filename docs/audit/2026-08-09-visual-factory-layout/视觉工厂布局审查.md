# 视觉工厂布局审查

## 审查范围

- 当前“生成工作台 / 封面工作室”截图。
- `visuals.js` 中生成工作台、IP 资产与提示词、成品历史三个页签的组件结构。
- `app.css` 中视觉工厂 v2/v3 并存样式及响应式规则。
- `visuals.py` 中封面候选、封面合集、图文文档和视觉资产的软删除接口。

## 总体结论

问题不是简单的间距不好看，而是旧版视觉工厂样式与新版组件结构叠加后产生了系统性冲突：容器断点按整个浏览器宽度判断，没有按去掉侧边栏后的真实可用宽度判断；配置项被拆到主表单和右侧检查栏两处；自定义提示词预设编辑器被放错页签；上传卡片沿用了不匹配的新旧 DOM 选择器；成品历史只有合集级归档入口，候选级删除虽然有后端接口但前端没有入口。

## 逐步健康度

1. 进入视觉工厂：一般。导航和三个主页签可识别，但标题区、状态条、页签、工作室切换连续叠加，首屏层级过多。
2. 选择封面或图文工作室：较差。使用两张大卡作为二级切换，挤占首屏空间，并与顶部主页签形成重复导航。
3. 绑定稿件和优化提示词：较差。流程卡过宽、内容过长；项目没有可用稿件时只表现为灰色按钮，没有明确下一步。
4. 配置生成参数：较差。比例、数量、人物参考图被放进右侧“生成检查”，配置与校验职责混杂。
5. IP 资产与提示词：较差。上传卡片 CSS 仍假设存在图标节点，当前 DOM 不匹配；提示词预设只能查看，自定义预设编辑器反而出现在生成工作台底部。
6. 成品历史：不完整。合集归档和图文文档归档仍存在，但单个封面候选没有删除入口；“归档”文案也容易让用户误以为删除能力消失。

## 已确认根因

1. `.visual-v3-grid` 固定为 `1fr + 340px`，但断点只看浏览器宽度 `1280px`，没有扣除约 306px 的侧边栏，也没有考虑浏览器缩放。
2. 页面缺少自身最大宽度和容器查询，超宽时过度拉伸，中等宽度时主表单被右栏挤压。
3. `.visual-v3-summary` 同时承担检查、比例、数量、人物参考图与最终 CTA，职责过多。
4. `.visual-preset-editor` 是生成网格的第三个子项并跨满两列，放置位置错误。
5. `.visual-upload-card > span:nth-of-type(2)` 与当前只有一个 `span` 的 DOM 不匹配，文本容器没有获得预期的 flex/min-width 样式。
6. 旧规则 `.visual-batch-items button` 会污染候选卡内的普通操作按钮，新规则没有完整重置。
7. 后端已有 `DELETE /covers/{cover_id}`，前端没有 `deleteCover` 方法及候选级操作入口；资产删除接口也没有在当前资产卡中暴露。
8. 大量辅助文字使用 9–10.5px 字号，信息虽然多，但可读性和层级都不足。

## 推荐调整

### A. 生成工作台

- 将“封面 / 图文”改成紧凑分段切换，不再使用 74px 高的大卡。
- 页面主体限制在 1440–1520px，并使用容器查询：可用宽度低于约 1180px 时，右侧检查栏自动落到主流程底部。
- 主流程只保留四步：来源、提示词、内容与规格、生成方式。
- 把比例、候选数量、人物参考图移回“内容与规格”；右栏只显示“还缺什么、预计生成什么、生成按钮”。
- 提示词结果默认折叠，只显示优化状态和“展开查看最终提示词”。

### B. IP 资产与提示词

- 改成两个明确分区：左侧“人物/Logo/风格参考资产库”，右侧“封面提示词/图文提示词预设库”。
- 修复上传卡片 DOM/CSS 对应关系，卡片使用图标、标题、说明和明确上传按钮四个稳定区域。
- 将自定义预设编辑器移入该页签，增加封面/图文筛选、复制内置预设、编辑自定义预设、归档自定义预设。
- 每张资产卡恢复“设为默认、用于本次任务、删除/归档”操作。

### C. 成品历史

- 用“生成批次列表 → 当前批次候选”两级结构，避免所有图片一次性铺满。
- 每个候选恢复：查看、下载、复用参数、选定、删除。
- 批次级保留“重命名、归档整个批次”；图文文档保留“继续编辑、定稿、归档”。
- 对已同步到计划/发布的成品禁止直接静默删除，先提示替换或解除关联。
- 将“归档”与“删除”解释清楚，并提供“已归档”筛选，避免用户认为入口消失。

## 验收标准

- 1366、1440、1920 宽度及 125%/150% 缩放下无横向溢出、遮挡和竖排文字。
- 三个页签首屏都能看见主任务和主要 CTA。
- 所有长标题、提示词、资产名都采用换行或省略，不撑破网格。
- 生成按钮禁用时明确显示缺失项，并可一键定位。
- 封面候选、封面批次、图文文档和视觉资产均有与后端一致的归档/删除入口。
- 键盘焦点、按钮对比度、触控目标与错误恢复需要在实现后单独验证。

## 证据限制

当前视觉证据只覆盖桌面宽屏下的封面工作室首屏；IP 资产与提示词、成品历史的结论来自同一版本代码结构与样式检查。尚未通过用户指定浏览器验证键盘、缩放和多断点实际渲染。

# 2026-08-05 全应用交互审查与修复

## 1. 审查目标与结论

本轮针对用户反馈的“按钮只有提示、没有表单、没有结果、前后端断开”做源码级、API 级和 Chrome 实际点击审查。结论：反馈属实，原实现存在多个 `FAKE_SUCCESS` 和固定示例引用；本轮已消除核心流程中的这些断点，并把源码服务保持在真实模式供验收。

当前健康度：

- 核心交互闭环：通过。账号添加、对标添加、来源选择、设置保存、真实测试、IP 版本、访谈、组合拆解和模式卡均有输入、后端动作与结果回显。
- 真实 Provider：抖音/TikHub、DeepSeek、百炼 ASR 均通过当前轮真实输入测试。
- 全业务 API 链：通过 50/50，从雷达一直到发布、快照、复盘和规则版本。
- 发行：未执行。按用户要求，源码验收前不打包 EXE。

## 2. 发现并修复的问题

1. **账号运营“添加账号”是假成功**：原按钮只弹提示，没有输入入口。现为可访问模态框，包含平台、主页链接/ID、数据模式、显示名与同步频率；后端真实解析后才落库，并回显账号资料和首个快照。
2. **账号趋势误导**：只有一个快照时仍画成面积三角形。现明确显示“首个快照”，第二次真实同步后才绘制趋势。
3. **运营周期只在前端或内存变化**：现按用户写入 `app_settings`，重启后保留。
4. **总台混用固定案例**：周目标、待拆解数、行动队列、重要信号此前含硬编码。现全部从账号快照、信号、来源内容、创作项目、发布与快照计划聚合；无数据时显示真实空状态。
5. **内容提取固定使用 `SG-2031`**：现必须从真实雷达信号下拉框选择来源，再生成单次确认计划。
6. **内容拆解来源链固定使用 `SG-2031`**：现从 `source_contents.signal_id` 回溯；没有雷达来源时不伪造节点。
7. **模式卡固定写入案例名称**：现打开编辑弹窗，由用户填写名称和证据说明，并以草稿持久化。
8. **转为选题固定标题与固定选题 ID**：现使用当前拆解的真实主题和来源链创建创作项目。
9. **IP 档案创建/编辑只有提示**：现创建不可变版本并可激活；访谈可以开始、回答、暂停和保存进度。
10. **组合拆解按钮无实际结果**：现保存真实分析 ID、实际表现分组和备注，并在列表回显。
11. **系统设置“保存成功”无结果**：现持续显示保存分区、摘要和时间；数据源测试显示账号名称、粉丝、作品与简介，并提供带入账号/对标入口。
12. **模型配置被测试脚本污染**：旧冒烟脚本曾在非隔离环境写入 `models.example.com`。脚本现在遇到真实模式立即停止；真实环境已恢复 DeepSeek Base URL、Bearer 鉴权和任务模型，并重新通过最小生成。
13. **侧栏自动收起**：分组默认展开，仅在用户点击分组标题时切换；跨页面导航不会自动收起。
14. **Escape 只改 CSS、未改 Vue 状态**：现通过触发真实关闭按钮同步组件状态，可再次打开。

## 5. UX 与无障碍审查

做得较好的部分：输入—提交—处理中—成功/失败—后续入口已连贯；真实/演示状态可见；外部失败不再伪装成功；模态框有 `role="dialog"`、`aria-modal`、标题关联和关闭按钮标签；保存结果使用 `aria-live`；侧栏分组暴露 `aria-expanded`；键盘 Escape 已验证。

仍需继续关注：尚未完成全站 WCAG 2.2 AA 自动扫描；尚未系统验证焦点陷阱、所有表单错误的字段级关联和高对比度模式。当前证据只能支持“核心弹窗可键盘关闭、关键状态可读”，不能宣称全站无障碍完成。

## 6. 未伪装为完成的边界

- 小红书、视频号、B站、快手、微博、TikTok 已有平台入口和 Provider 映射，但缺少用户提供的逐平台真实公开样本，因此保持 `PARTIAL`。
- 平台媒体自动下载没有授权 Provider；内容提取的真实主链为用户上传音频→ASR，或平台存在可用原生字幕。
- 自动抓取发布后指标尚未接入授权 Provider；到期计划会停在人工录入，不生成指标。
- Embedding 和 TTS 未接入，设置页明确标记。
- 远程登录与团队级身份认证未实现；当前应用只绑定回环地址。
- 本轮不打包 EXE。

## 7. 体验方向与优先级

产品目标仍应坚持“证据先于结论”：任何卡片必须能回答来源、状态、失败原因与下一步。下一迭代的最高价值不是增加页面，而是补齐各平台真实样本契约、平台媒体/指标授权 Provider，以及完整 WCAG 自动化与键盘巡检。
